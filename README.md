# Macro Strategy Agent

Pipeline that predicts which trading-strategy permutations will perform best over the next 5 trading days,
using macroeconomic event surprises (CPI, FOMC, employment, etc.).

**Flow:** Apify calendar scrape (last 180 days) -> Tavily news -> yfinance prices -> backtest of 24 strategy
permutations (the "trading logs") -> DuckDB join -> features -> LightGBM walk-forward validation ->
Sharpe / Sortino / Max Drawdown report, charts, macro summary.

> **Assumption:** no trading logs were provided, so they are generated by backtesting MA-crossover and
> breakout strategies on SPY daily bars across a parameter grid (`src/backtest.py`).
> AI assistance (Claude) was used to write this code; I reviewed and ran it myself.

## Quick start
```bash
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env                                    # then fill in the keys
python run_pipeline.py --synthetic                      # offline smoke test (fake data!)
python run_pipeline.py                                  # REAL run: scrape + news + model
```
Outputs: `reports/evaluation_report.md`, `reports/macro_summary.md`, `outputs/charts/*.png`, `outputs/metrics.json`.

## Reproducing with Apify / Tavily
- Actor ID: `pintostudio/economic-calendar-data-investing-com` (pay per result, about $0.01 per event)
- Input template: `config/apify_input.json` (dates are overwritten per chunk by the code).
  Verify the field names against the actor's **Input -> JSON** tab in the Apify Console.
- The scrape runs in 30-day chunks and caches each chunk in `data/raw/`, so a re-run never pays twice.
  `python -m src.ingest_apify --dry-run` prints the estimated cost without calling Apify.
- `python run_pipeline.py --skip-scrape` reuses cached data.
- Tokens go in `.env` only (never committed): `APIFY_TOKEN`, `APIFY_ACTOR_ID`, `TAVILY_API_KEY`.

## Leakage controls (details in the evaluation report)
Expanding-window walk-forward, 5-day embargo between train and test, signals shifted one day,
surprise scaling from past data only, non-overlapping evaluation periods.

## Dashboard (optional)
1. Run the real pipeline, then commit `outputs/` and `reports/` (the API serves these files; it needs no keys).
2. **Render:** New -> Web Service -> connect the repo. `render.yaml` is picked up automatically.
3. **Vercel:** import the same repo, set **Root Directory = `web`**, no build command.
   Edit `web/config.js` so `API_URL` is your Render URL, commit, push.
4. Do not put API tokens on Vercel or Render; neither needs them.
Free Render services sleep when idle, so the first load can take about a minute.

## Layout
```
run_pipeline.py        one-command pipeline
src/ingest_apify.py    calendar scrape + parsing (UTC and US/Eastern timestamps)
src/ingest_tavily.py   news
src/backtest.py        strategy permutation logs
src/features.py        surprise, calendar-distance, volatility, time features
src/db.py              DuckDB join (events + features + logs -> panel)
src/model.py           LightGBM + walk-forward
src/metrics.py         Sharpe, Sortino, Max Drawdown
src/visuals.py         charts
src/summary.py         1-page macro outlook (template-based)
api/  web/             optional FastAPI + static dashboard
```
## Results note
Over ~15 walk-forward periods the model did not beat the historically-best or SPY buy-and-hold baselines
(Sharpe 0.16 vs 1.22 and 1.69). With this few periods the result is inconclusive, not evidence for or against
an edge. The event tagging was corrected after inspecting the heatmap (weekly jobless claims had been
mislabelled as employment events).
